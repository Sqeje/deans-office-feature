# AcademicPerformance

Модуль владеет семестрами, дисциплинами групп, персональными текущими оценками и итогами. Зарегистрирован через IAppModule/AppModules. Хранение — EF/PostgreSQL; календарные даты — DateOnly, изменение — DateTimeOffset UTC. Фиктивное учебное наполнение добавляется только при Demo:Enabled; повторный seed не заменяет результаты сотрудников.

## Контракты

- GET `/api/academic-performance/semesters` — семестры своего университета, defaultSemesterId.
- GET `/api/academic-performance/student?semesterId=...` — персональные дисциплины и summary. StudentId и UniversityId берутся из ICurrentActor. Только роль Student со студенческим профилем.
- GET `/api/academic-performance/staff/groups` — группы с назначенным grades.write.
- GET `/api/academic-performance/staff/groups/{groupId}/students` — студенты доступной группы.
- GET `/api/academic-performance/staff/students/{studentId}?semesterId=...` — результаты доступного студента.
- PUT `/api/academic-performance/staff/students/{studentId}/courses/{courseId}/result` — локальный итог `{kind, value}`; CSRF, политика grades.write, AccessGuard по фактической группе студента и дисциплины. Примеры: `{ "kind": "grade", "value": 4 }`, `{ "kind": "credit", "value": null }`, `{ "kind": "failed-credit", "value": null }`, `{ "kind": "pending", "value": null }`.
- GET `/api/academic-performance/staff/journal-courses` — назначения преподавателя или дисциплины групп с grades.correct у декана.
- GET `/api/academic-performance/staff/courses/{courseId}/journal` — ведомость курса: студенты и занятия.
- PUT `/api/academic-performance/staff/lessons/{lessonId}/journal` — локальная оценка/посещаемость одного или нескольких студентов; CSRF, версия журнала и AccessGuard по фактической группе.

Преподаватель может выставить оценку один раз, но не изменить её позднее; посещаемость остаётся редактируемой. Декан с grades.correct может исправлять оценки, а сервер требует причину для каждого изменения уже выставленного значения. Причина последней коррекции хранится в записи журнала. Каждая новая, исправленная или снятая оценка создаёт персональное уведомление этому студенту в том же транзакционном сохранении.

Для экзамена допустимы 2–5; зачёт не является численной оценкой. Итог 2/незачёт даёт задолженность, pending — отсутствие итога. Среднее считается только по численным итогам, включая 2; при отсутствии итоговых оценок null. Стипендия не вычисляется. Главная и раздел используют один PerformanceResponse и один серверный PerformanceReader; копии сводки не хранятся.

Summary дополнен `credits` (количество итогов credit, без экзаменационных оценок и незачётов) и nullable `nextExam: { courseId, name, date }`. Ближайший экзамен — самая ранняя дата сегодня или позже у exam/pending, с исключением уже выставленных итогов, зачётов и записей без даты. «Сегодня» определяется на сервере через TimeProvider и Europe/Moscow — текущую зону по умолчанию из DESIGN.md. Компонент AcademicSummary экспортируется модулем для владельца главной; ссылка сохраняет semester и открывает discipline=courseId. Итоговую композицию главной определяет владелец срезов 1–2. Дополнение меняет только модуль, его тесты и сгенерированную OpenAPI-схему; новая миграция не нужна.

PUT создаёт либо изменяет один результат студента/дисциплины; повтор с теми же значениями не создаёт запись или новый аудит. Изменение и аудит фиксируются одним SaveChanges. Источник с SourceId не редактируется этой операцией; импорт в срез не входит. При конкурентном создании повторяющегося результата возвращается 409. Конкурентные изменения существующего итога пока используют последнюю успешную запись; версионирование/история ведомости в этот срез не входят.

401 — нет сеанса; 403 — нет прав/назначения; 404 — объект своего университета или семестр не найден; 400 — валидация/CSRF; 409 — конфликт или результат источника. Формат ошибок — Kernel Problem Details с code/traceId. Межмодульное чтение профилей/групп — через Identity.IStudentDirectory.

## Схема и проверки

Миграции `20261110120120_AcademicPerformance` и `JournalGradeCorrectionReason`: AcademicSemester, AcademicCourse, AcademicResult, AcademicGrade, журнал занятий и сохранённая причина последней коррекции оценки. FK ограничивают вуз/группу дисциплины, студента и текущих работ; unique ограничивает один итог и одну запись журнала для пары «занятие/студент». Перевод студента между группами с существующими результатами требует отдельного сценария; текущая схема запрещает нарушение связи, а не перемещает учебную историю автоматически.

AcademicPerformanceTests работают с уникальными PostgreSQL-БД, созданными на сервере TEST_DATABASE (нужен CREATEDB). Проверяют изоляцию, CSRF, доступ по группе/вузу, отзыв прав, валидацию, создание/повтор, аудит, ограничения БД и сохранение после нового сеанса/seed. UI-приёмка и текст PR — в [срезе 6](../../../../docs/slices/6-academic-performance-api.md).
