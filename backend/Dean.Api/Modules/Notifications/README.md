# Notifications

Модуль владеет сообщениями и персональным прочтением. Регистрация через IAppModule/AppModules. PostgreSQL — источник истины. Нет автоматической подмены демонстрацией, email/push и общей шины событий.

API относительно /api/notifications:
- GET /student: items и unreadCount; новые первыми, при равном времени — ID по убыванию.
- POST /student/{id}/read и /student/read-all: идемпотентное прочтение, 204. Read-all использует один снимок SQL; новые сообщения остаются непрочитанными.
- POST /staff/announcements: operationId, title (1–200), text (1–4000), простой текст. 201 при создании, 200 при точном повторе, 409 при другом содержимом с прежним ключом. Аудит и сообщение атомарны.

Студент видит свои сообщения и все объявления текущего вуза, включая прежние объявления при новом присоединении. StudentId/UniversityId — только из actor. Чужое сообщение — 404. Публикация требует announcements.publish и AccessGuard для вуза actor. Все мутации требуют CSRF. DTO публикуются OpenAPI; ошибки Problem Details с code/traceId.

IRequestNotifications.StatusChanged вызывается Requests при каждой успешной смене статуса. Контракт только добавляет сообщение в текущий scope/DbContext, не вызывает SaveChanges: заявка, история, аудит и сообщение атомарны. EventKey request:ID:version уникален в вузе. Конфликт и откат не оставляют сообщения. Ссылка UI — существующий requestDetailsUrl; причина отклонения доступна только в заявке. Ретроспективных сообщений для старых статусов нет.

Прочтение хранится отдельно для каждого студента и объявления. UTC-моменты отображаются ru-RU/Europe/Moscow. Перезагрузка и новый вход сохраняют прочтение; UI обновляет ленту при переходе и фокусе окна, не использует polling/WebSocket. Открытие ссылки само не отмечает сообщение прочитанным.

Миграция NotificationsPersistence создаёт NotificationMessages/NotificationReads и заменяет уникальный индекс StudentProfiles(UserId,UniversityId) альтернативным ключом для составных FK. Существующие данные сохраняются. Новых разрешений и зависимостей нет.

Schedule отсутствует: перенос пары и его согласованная интеграция остаются зависимостью от срезов 3–4. Уведомления об оценках не реализованы. План, результаты и черновик PR — docs/slices/10-notifications-integration.md.
