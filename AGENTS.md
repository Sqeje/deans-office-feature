# Работа в проекте

- Прочитай README и docs/ARCHITECTURE.md; требования текущего среза важнее догадок. Для нового модуля/источника используй docs/EXTENDING.md.
- Перед изменением интерфейса прочитай [docs/DESIGN.md](docs/DESIGN.md): текстовое описание имеет приоритет. При необходимости один раз в начале просмотри нужные изображения из docs/view-references/ и сохрани краткие заметки; повторный просмотр — только для конкретной неясности или нового референса. Следуй общим токенам, компонентам, правилам текстов, статусов и адаптации; готовый интерфейс проверяй визуально. Макет не расширяет объём среза и не меняет серверные права или контракты без согласования.
- Один срез — одна feature-ветка и PR. Не пушь и не публикуй без разрешения пользователя.
- Работай в папках своего модуля backend/Dean.Api/Modules и frontend/src/modules. Не реализуй соседние разделы.
- Общие файлы Program.cs, AppDbContext, навигация, API-клиент, зависимости и миграции меняй минимально, отмечай изменения в PR.
- Доступ к данным проверяет сервер. StudentId и UniversityId получай из доверенного сеанса/профиля, не из тела запроса. Студенческие выборки ограничивай обоими идентификаторами. Для сотрудника используй политику операции и AccessGuard по университету/группе объекта; роль Staff сама по себе не даёт прав.
- Небезопасные HTTP-методы требуют CSRF. Не добавляй JWT, localStorage-сеансы или CORS без архитектурного решения.
- Контракты генерируются из OpenAPI: npm run api:generate. Не правь schema.d.ts вручную.
- Не добавляй секреты, реальные персональные данные, универсальные репозитории или новые технологии без необходимости.
- EF-миграции: правила docs/CONTRIBUTING.md. Не редактируй применённые миграции.
- Общий путь запуска/проверки — [docs/AUTOMATION.md](docs/AUTOMATION.md): `./dev.ps1 doctor`, `./dev.ps1 up`, `./dev.ps1 check`. Check выполняет сборки, серверные и браузерные тесты в изолированном Docker-окружении и не трогает host node_modules. При отсутствии Docker используй локальный путь: dotnet build/test с одноразовой PostgreSQL и npm run build; npm ci нужен при отсутствующих/неполных зависимостях или изменении lock-файла, с остановленным Vite. Сообщай фактические результаты и ограничения; DryRun не является успешным тестированием.
- Прежде чем объявить проверку заблокированной окружением, прочитай [docs/LOCAL_ENVIRONMENT.md](docs/LOCAL_ENVIRONMENT.md). На Windows проверь локальный SDK `.tools/dotnet`; `scripts/Enter-DevEnvironment.ps1` запускай в том же shell-вызове, что и dotnet. Перед npm ci останови только Vite этого проекта и исключи параллельную установку в том же каталоге; не завершай все node-процессы. После ошибки установки сначала восстанови зависимости, не считай отсутствие tsc отдельной неисправностью.

- Модули регистрируются через IAppModule/AppModules и FrontendModule/modules/sections. Kernel не содержит предметных правил. Межмодульные вызовы — через явные контракты.
- Формат ошибок — Problem Details с code/traceId. Внешние данные проходят получение → интерпретацию → атомарное применение модулем; сопоставление по UniversityId/SourceId/ExternalId. Импортированные поля принадлежат источнику.
