# Следующие вертикальные срезы

Начинать после интеграции Kernel. Один владелец среза отвечает за студенческую и служебную стороны одного сценария.

| Срез | Результат | Право сотрудника |
|---|---|---|
| Расписание и первый источник | Настроенный адаптер обновляет занятия; студент видит день и неделю; отображается время обновления | schedule.write; для подключения sources.manage |
| Обращение от подачи до решения | Студент создаёт заявку, сотрудник назначенной группы меняет статус, студент видит историю | requests.manage |
| Учебные результаты | Сотрудник вносит локальные результаты назначенной группы; студент видит свои оценки и сессию | grades.write |
| Объявления | Сотрудник публикует объявление в своём вузе, студенты выбранной аудитории видят его | announcements.publish |
| Персональные уведомления | Изменение статуса заявки порождает уведомление; студент отмечает его прочитанным | Внутренний контракт Requests → Notifications |
| Рабочее место сотрудника | Сводка задач по уже готовым модулям и его разрешениям | Разрешения исходных модулей |
| Публичная часть абитуриента | Программы и явно обозначенные демонстрации без подачи заявлений и хранения персональных данных | Публичный frontend |

Первую параллельную работу троих распределить на расписание, обращения и результаты. Для каждого отдельно согласовать предметные поля/статусы; общий контекст и правила расширения уже заданы Kernel. Notifications подключается к Requests явным контрактом без общей шины сообщений. Общую миграцию интегрирует один участник последовательно.
