# Работа втроём

1. Установите Git, Docker с Compose; для разработки вне контейнеров — .NET SDK 10 и Node.js 24.
2. `git clone <URL-репозитория>`; `cd <каталог>`; выполните README.
3. `git switch main`, `git pull --ff-only`, `git switch -c feature/<module>-<scenario>`.
4. Прочитайте docs/EXTENDING.md и docs/SLICES.md. Передайте своему Codex AGENTS.md и заполненный docs/SLICE_TEMPLATE.md. Попросите сначала изучить модуль, затем реализовать один сценарий с тестами. Не поручайте параллельно менять общую инфраструктуру.
5. Разделение первой работы: участник 1 — Schedule; участник 2 — AcademicPerformance; участник 3 — Requests. Notifications — следующий срез. Identity остаётся общим контрактом; изменения согласовываются.
6. Перед PR выполните `npm ci` и `npm run build` в frontend; `dotnet build backend/Dean.Api/Dean.Api.csproj`; `dotnet test backend/Dean.Api.Tests` с TEST_DATABASE на отдельную пустую PostgreSQL. Тест создаёт демо-аккаунты со случайными паролями, поэтому для повторного запуска нужна новая тестовая БД.
7. Проверьте 360 px, вход двумя аккаунтами, ошибки сети. Создайте PR в main, укажите общие изменения и приложите результаты проверок. Другой участник делает ревью. Объединяйте PR последовательно, после зелёного CI. Публикация/отправка Codex — только с разрешения человека.

## Миграции

Владелец PR создаёт миграцию после обновления ветки от main: `dotnet tool restore`, затем `dotnet ef migrations add <ModuleScenario> --project backend/Dean.Api`. Snapshot общий. Не исправляйте его конфликт вручную вслепую: если миграция ещё нигде не применялась, удалите свою последнюю миграцию `dotnet ef migrations remove`, подтяните main и создайте заново. Если уже применялась — новая корректирующая миграция, без переписывания истории. Назначьте одного интегратора на последовательность PR со схемой.

Проверяйте миграцию на пустой БД и на копии предыдущей схемы. В production сначала резервная копия, затем отдельный initialize, затем API. Автоматического удаления данных и отката нет.

## Контракты

Запустите API на localhost:8080 и выполните в frontend `npm run api:generate`. Добавьте сгенерированный schema.d.ts в тот же PR. Для API используйте общий openapi-fetch клиент, для мутаций — CSRF-заголовок. Не создавайте второй транспорт. Модули подключаются через AppModules на сервере и modules/sections на клиенте; доменный код в Program не добавляется.
