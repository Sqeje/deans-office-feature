# Срез 5 — интерфейс успеваемости и сессии

Статус: frontend реализован и проверен на демонстрационных данных; обязательные серверные проверки недоступны. Ветка: `feature/academic-performance-ui`.

## Согласованный план

Цель: студент выбирает семестр, открывает дисциплину и видит текущие оценки, итог, задолженность и дату экзамена. Только frontend с явно обозначенными вымышленными данными; сервер, запись сотрудником, импорт и сводка главной — срез 6.

- Сохранить существующий FrontendModule и `/student/academic-performance`; семестр и дисциплину хранить в query-параметрах. Подробности — встроенная панель с переносом фокуса.
- Локальные типы и заменяемый загрузчик в модуле AcademicPerformance. Два наполненных семестра и один пустой; по умолчанию осень 2026. Один демонстрационный набор для вошедших студентов, без имитации персональной интеграции.
- Оценки 2–5, зачёт, статусы passed/debt/pending. Задолженность задаётся явно. Среднее включает все числовые итоги, в том числе двойки, и исключает зачёты и невыставленные результаты. Календарные даты не зависят от зоны браузера.
- Загрузка, ошибка с повтором, пустые данные и отсутствие оценок; сбои загрузчика задаются тестами, без технических переключателей в продукте.
- Минимальные общие изменения: токены DESIGN.md, локальный Inter с лицензией, компоненты карточки, статуса, выбора и skeleton, совместимый вариант Button, доступность и пометка прототипа. Структуру навигации сохранить.
- API, OpenAPI, Kernel, разрешения и БД не менять. Источник истины этого этапа — отдельные фикстуры, без HTTP и fallback при ошибке API. Изоляция реальных оценок студентов/вузов — срез 6.

## Визуальные ориентиры

DESIGN.md — основной стандарт. R2 просмотрен один раз: светлый тёплый фон, тонкие рамки, синие действия, спокойные компактные статусы. Презентационный коллаж не воспроизводить. Полный редизайн оболочки не входит в задачу.

## Проверки и готовность

- Браузер: семестр → дисциплина с задолженностью → текущие оценки, итог, задолженность и экзамен; компьютер и 360 px.
- Playwright: URL, обновление, «Назад», неизвестная дисциплина, смена семестра без устаревших подробностей; загрузка, ошибка/повтор, пустой семестр, отсутствие оценок.
- Тесты расчётов: среднее с двойкой, исключение зачёта/pending, отсутствие среднего, явная задолженность, календарные даты в разных зонах.
- Доступ: анонимный сеанс и сотрудник без студенческой области. Подмена HTTP сеанса в UI-тестах проверяет клиентское поведение, а не серверную безопасность.
- Визуально: 360/390/768/1024/1280/1440 px, длинный текст, клавиатура, фокус, контраст, масштаб 200%, reduced motion; снимки сохранить.
- Регрессии: вход, профиль, выход, кабинет сотрудника.
- Обязательные команды: npm ci, npm run build, dotnet build, dotnet test на одноразовой PostgreSQL; проверка Impeccable.

## Зависимости и ограничения

Identity/Kernel реализованы; Schedule, Requests, Notifications и сервер AcademicPerformance пока заглушки. Для среза 5 они не требуются. Повреждённый README backend AcademicPerformance содержит устаревшие указания: подключение определяется ARCHITECTURE.md.

На старте npm/.NET/Docker отсутствовали в PATH. Локальный npm 11.6.2 получен в игнорируемой `.tools/`; Chromium установлен для Playwright. .NET SDK и одноразовая PostgreSQL недоступны. Команды dotnet build/test были вызваны и остановились на отсутствии dotnet; серверные проверки не выполнены.

Локальный коммит разрешён пользователем с названием `feat: add demo academic performance interface`. Push, публикация и удалённый PR не выполнялись.

### Модули и совместимость

Предметные типы, фикстуры, загрузчик, расчёты, экран и стили находятся в frontend-модуле academic-performance. PerformanceLoader принимает semesterId и AbortSignal и возвращает SemesterPerformance; его можно заменить при интеграции среза 6. Это локальный контракт представления, не спецификация будущего серверного API. Фикстуры не содержат StudentId/UniversityId: общий вымышленный набор не привязан к профилю. Выбор сохраняется только в URL.

Общие изменения: style.css (токены/шрифт/фокус/фон и карточки), Cabinet (skip-link, фокус и пометка прототипа), Button (добавлен primary, прежние варианты сохранены), общие UI-примитивы и их CSS. Playwright запускает Vite через node напрямую, без зависимости от npm в PATH. DESIGN.md содержит журнал этих решений.

Публичные API, schema.d.ts, разрешения, реестры модулей, backend и миграции не менялись. Новых runtime-зависимостей нет. Локальные файлы Inter с кириллицей и латиницей получены из @fontsource-variable/inter 5.2.8; SIL OFL лежит рядом со шрифтами. Тестовый HTML/TSX entry находится в tests/fixtures, production-сборка его не включает.

### Воспроизведение

При работающем API войти студентом, открыть «Успеваемость», выбрать «Осень 2026 · 7 семестр», открыть «Международное право». В подробностях: оценки 4 и 5, итог 2, задолженность с пояснением, экзамен 18 января 2027 года. Выбрать другой семестр, вернуться кнопкой «Назад», обновить страницу. «Весна 2027» демонстрирует отсутствие дисциплин.

Автоматическая UI-проверка не требует API. Из frontend:

```powershell
node ../.tools/package/bin/npm-cli.js run build
node node_modules/@playwright/test/cli.js test tests/performance.spec.ts tests/performance-regression.spec.ts --workers=1
```

На обычной машине с npm использовать npm ci / npm run build и npx playwright test с указанными двумя файлами. Снимки сохраняются в frontend/test-results; они игнорируются Git и при необходимости прикладываются к PR вручную.

Для локального просмотра самого экрана без Identity API запустить из frontend `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort` и открыть `http://127.0.0.1:5173/tests/fixtures/performance.html?semester=2026-autumn&discipline=international-law`. Это существующий тестовый entry только для разработки, без оболочки кабинета и без проверки авторизации; production-сборка его не включает. Настоящий маршрут кабинета требует работающего backend и входа.
