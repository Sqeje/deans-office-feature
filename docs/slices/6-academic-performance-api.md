## Цель и демонстрация

Два студента видят свои различные серверные результаты. Сводка главной совпадает с разделом того же семестра. Сотрудник с `grades.write` вносит локальный итог студента назначенной группы; после обновления результат и сводка совпадают и сохраняются после перезагрузки.

## Границы и зависимости

Срез 5 доступен: три представления, query-параметры и локальная модель. Identity/Kernel работают; StudentHome — заглушка. Добавляются только сервер AcademicPerformance, загрузка существующего UI, его сводка на главной и минимальная форма сотрудника. Расписание, заявки, уведомления, полный преподавательский журнал, стипендия, реальный импорт и университетские системы не входят.

## Решение и данные

- AcademicPerformance владеет семестрами университета, дисциплинами группы/семестра, персональными итогами и текущими оценками. Даты аттестаций — DateOnly; время изменения — UTC DateTimeOffset. Шкала 2–5, обычный зачёт без численной оценки. Итог экзамена 2 и незачёт означают задолженность, отсутствие итога — pending. Среднее — только численные итоговые оценки, включая 2; при их отсутствии null. Стипендия не вычисляется.
- Источник истины — PostgreSQL. Семестры и данные прототипа явно вымышленные, заполняются только при Demo:Enabled. Повторный seed не заменяет введённые результаты. Нет скрытой подстановки frontend-фикстур при ошибках API.
- Сервер возвращает список семестров с defaultSemesterId и персональные дисциплины со сводкой. Сводка главной использует тот же endpoint и серверный расчёт, что и раздел. Локальный view-adapter переводит сгенерированные DTO в представления среза 5.
- Identity предоставляет узкий интерфейс чтения групп/студентов с UniversityId. Студент ограничен своим StudentId/UniversityId из ICurrentActor; сотрудник — политикой grades.write и AccessGuard по фактической группе объекта. Идентификатор студента в staff-маршруте — объект действия, не доверенный контекст.
- PUT итогового результата идемпотентен по студенту/дисциплине; мутация и аудит сохраняются одним SaveChanges. Проверяются шкала и вид аттестации; чужие университеты не раскрываются. Импортированные записи не редактируются этой операцией.

## API

- GET `/api/academic-performance/semesters`: доступные семестры своего университета, defaultSemesterId.
- GET `/api/academic-performance/student?semesterId=...`: свои дисциплины, текущие/итоговые оценки, задолженности, даты и summary.
- GET `/api/academic-performance/staff/groups`: только назначенные группы.
- GET `/api/academic-performance/staff/groups/{groupId}/students`: студенты доступной группы.
- GET `/api/academic-performance/staff/students/{studentId}?semesterId=...`: результаты студента доступной группы.
- PUT `/api/academic-performance/staff/students/{studentId}/courses/{courseId}/result`: локальный итог `{kind, value}`; grades.write, проверка группы, CSRF, аудит.
- Ошибки Kernel Problem Details: 400 validation/CSRF, 401 сеанс, 403 права/группа, 404 объект/семестр, 409 конфликт записи. Существующие identity-контракты не меняются; OpenAPI-клиент генерируется.

## Интерфейс

Сохраняются существующие композиция успеваемости, токены и компоненты. Основной стандарт docs/DESIGN.md (разделы 10, 12–18). Предпросмотр среза 5 остаётся явно демонстрационным через явные props; рабочий маршрут использует API. Форме сотрудника достаточно последовательности группа → студент → семестр → дисциплина → итог → сохранение. Загрузка, пустые списки, ошибки с повтором, 401/403, валидация и успех отображаются явно. Смена выбора отменяет старые запросы и не переносит форму на другого студента. Общая оболочка сохраняется.

## Воспроизведение приёмки

1. Выполнить обычный запуск README с Demo:Enabled и тремя разными паролями. Использовать отдельные окна/профили браузера для student1@demo.invalid, student2@demo.invalid и staff@demo.invalid.
2. На главной каждого студента выбрать «Осень 2026 · 7 семестр», открыть «Успеваемость», затем «Компьютерные сети»: у первого итог 2/задолженность, у второго 5/сдано.
3. У сотрудника открыть «Успеваемость» → ЦД-101 → Алексей Примеров → осень 2026 → Компьютерные сети → 4 → «Сохранить результат».
4. Обновить студенческий раздел: итог 4, задолженности нет. Перейти на главную того же семестра: сдано 2 из 4, средний 4, задолженностей 0. У второго студента остаётся средний 5.
5. Обновить страницы и повторить вход; результат остаётся. Выбрать весну 2027 — пустой семестр. Подробные проверки отсутствующих прав/чужой группы выполняются автоматическими серверными тестами, не ручным редактированием production.
