## Решения реализации
- Backend-модуль зарегистрирован одной строкой в AppModules; Kernel, разрешения и зависимости не изменены. RequestStatus опубликован enum через OpenAPI.
- Таблицы StudentRequest/RequestHistory и identity-последовательность номера созданы миграцией RequestsPersistence. Группа связана с университетом отдельно от текущего профиля: перевод студента не меняет старую область обработки.
- Ошибка первого теста перехода выявила, что EF трактовал новое событие с UUID как Modified. Новое событие явно добавляется; исходный тест после исправления прошёл. Тест с PostgreSQL-trigger, отклоняющим вставку аудита, подтверждает откат статуса и истории.
- После перехода на API общего хранилища заявок в памяти больше нет. Удалена прежняя RequestsSessionBoundary и её обёртка App.tsx; страницы Requests ключуются владельцем сеанса, загрузки отменяют применение запоздавшего результата при cleanup. Демо-источник выделен в demo.ts, используется явными фикстурами; рабочий UI использует только API.
- UUID незавершённой отправки сохраняется в URL operationId без полей обращения. При обновлении ввод нужно заполнить снова, повтор использует тот же ключ. После успеха URL заменяется, чтобы Back не возвращал использованный ключ.
- Независимое ревью агента обнаружило гонку ответа смены статуса и риск потери ключа операции при reload, затем случай Back после успеха. Исправлены защитой поколения страницы и сохранением/заменой URL; добавлены браузерные регрессии. Это отдельное ревью агента, не ревью участника команды.

## Демонстрация
1. Войти студентом → Заявки → Создать заявку → заполнить справку → Проверить → Отправить заявку. Получить номер; обновить и найти ту же заявку в списке и на главной.
2. В отдельном окне войти сотрудником с requests.manage → Заявки → назначенная группа → нужный номер → Взять на рассмотрение → ввести причину → Отклонить заявку.
3. Обновить подробности у студента: Отклонена, три события истории, та же причина. Повторить для заявления с периодом и завершить «Отметить готовой».
