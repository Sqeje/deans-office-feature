# Срез 4: серверное расписание

База: b1528d2 (срез 3). Ветка: feature/04-schedule-server. Commit/push не выполняются без отдельного запроса.

## Границы и принятые решения

- Личное расписание, занятия и контрольные текущего семестра, ближайшая пара на главной — PostgreSQL и API Schedule.
- Сохраняется интерфейс среза 3: сегодня/неделя, календарь, статусы, переносы и XLSX с русскими днями недели.
- Каталог и расписания преподавателей пока остаются отдельной явно подписанной демонстрацией. Даже ПИ-21 из каталога открывает демо-маршрут, не личную страницу.
- Два демо-студента относятся к ПИ-21 и ПИ-22. Старые вымышленные аккаунты и пароли сохраняются; старый общий demo-профиль второго студента переносится во вторую группу при инициализации.
- Уточнение 17.11: преподаватель имеет разрешение на ПИ-21 и ПИ-22, но может читать личное расписание и менять только собственные пары. Меняет время, адрес/корпус/аудиторию/этаж и отмену локального события. Преподаватель/группа не передаются через форму. Создание и удаление событий не добавляются.
- Демонстрационный импорт выполняется при initialize и в интеграционных тестах; ручного HTTP/UI-запуска и подключения реального университета нет.
- Серверное расписание не выводит реальных или автоматически придуманных оценок/результатов контрольных. Прежние визуальные результаты остаются только в отдельном frontend-демо.

## Данные и доступ

Владелец — Schedule. ScheduleEntry связан составными FK с группой и университетом, а TeacherUserId — с аккаунтом и тем же университетом. Отображаемое имя не определяет владение. Идентичность источника: UniversityId/SourceId/ExternalId с уникальным индексом; локальные записи не имеют внешней идентичности. Импорт хранит время получения. Version — concurrency token.

Сеанс определяет StudentId и UniversityId; IGroupDirectory в Identity разрешает группу только по обоим идентификаторам. Клиент не выбирает группу личного расписания. Для преподавателя используются policy schedule.write, актуальные серверные grants, AccessGuard фактической группы и совпадение TeacherUserId с доверенным UserId. Поиск записи ограничен университетом до проверки группы. Импортированные записи доступны только для чтения. PUT требует CSRF; запись события и schedule.updated сохраняются одним SaveChanges. Конфликт версии возвращает 409. Чужая пара той же группы возвращает 403, смена преподавателя — 400.

Все моменты и параметры SQL — UTC. Учебные дни/периоды — Europe/Moscow. Запрос ограничен годом, интервал занятия — 12 часами. Внешние сообщения не раскрывают исключения: Problem Details с code/traceId.

## API

- GET /api/schedule/context — группа текущего студента и происхождение данных.
- GET /api/schedule/mine?start=YYYY-MM-DD&end=YYYY-MM-DD&category=lesson|assessment — личные события за включительный диапазон московских дат.
- GET /api/schedule/next — ближайшее ещё не завершившееся неотменённое занятие того же студента.
- GET /api/schedule/teacher/context и /teacher/mine — аккаунт текущего преподавателя и только его пары в разрешённых группах.
- GET /api/schedule/staff — редактор только собственных событий преподавателя с такими же параметрами периода/категории; прежнего доступа ко всем парам группы больше нет.
- PUT /api/schedule/{id} — изменение разрешённой локальной записи с текущей version.

OpenAPI-типы генерируются npm run api:generate, вручную не редактируются. Запросы модуля используют общий client, check и csrf; второй транспорт не добавляется. Главная получает узкий frontend-контракт useNextLesson из Schedule. Переход ведёт на соответствующую неделю и конкретную запись. Возврат фокуса/видимости обновляет личное расписание; главная также обновляется раз в минуту. Ошибки не подменяются демоданными.

## Импорт

DemoScheduleSource → ScheduleInterpreter → ScheduleImportApplier через существующий ImportPipeline. Binding имеет фиксированный доверенный demo-контекст; публичного выбора университета/источника нет. Адаптер зарегистрирован как singleton, DbContext не захватывает.

Применение проверяет пакет, дубликаты, внешнюю идентичность и принадлежность всех групп университету. Одна транзакция на пакет, upsert, уникальный индекс и PostgreSQL advisory lock на университет/источник предотвращают дубликаты при параллельном запуске. Ошибка откатывает весь пакет; отсутствие записи не означает удаление. Локальные demo-занятия добавляются только при отсутствии стабильного ID и не перезаписываются seed после ручной правки.

## Общие изменения

- AppModules: регистрация ScheduleModule, Program и Kernel не меняются.
- Identity: узкий IGroupDirectory; используется Schedule для разрешения групп без записи в чужой модуль.
- DemoSeed: две группы/профиля и вызов модульной инициализации расписания; реальные аккаунты не затрагиваются.
- Новая миграция ScheduleStorage и автоматически созданный snapshot. Применённые миграции не меняются.
- shared/api: экспорт существующих check/csrf для модульного клиента; сгенерированный schema.d.ts.
- StudentHome: ближайшая пара через контракт Schedule; остальные разделы не реализуются заново.
- Новых зависимостей нет.

## Проверка

Новые серверные тесты используют отдельные временные базы PostgreSQL: два студента, spoofing группы, CSRF, разрешённая/чужая группа, другой вуз, read-only импорт, валидация, конфликт версии, аудит, отмена, совпадение next/mine и сохранность правки после повторной инициализации. Импорт проверяет повтор, параллельность, отсутствие удаления и откат как при ошибке интерпретации/ссылки, так и при ошибке PostgreSQL во время сохранения.

Браузерная приёмка: два реальных студента и сотрудник, изменение через UI на 360/1280, обновление главной/расписания, XLSX из серверных данных, отдельное демо каталога и отсутствие fallback при ошибке API. Сохраняются прежние тесты 360–1440, длинных строк, 200%, клавиатуры, календаря и сеанса.

## Дополнение 17.11: аудитория, отмена и соседние вкладки

- «Ауд.» — отдельный неизменяемый префикс поля; редактируется только обозначение аудитории. Локальный PUT нормализует префикс и запрещает пустой номер; импортированные поля источника не переписываются.
- Флажок отмены сбрасывает несохранённые правки к исходному событию, блокирует поля времени/места и отправляет только смену статуса с прежними значениями. Снятие флажка возвращает правку. Сервер отвергает совмещение отмены с изменением времени, аудитории, адреса, корпуса или этажа; version, собственность и аудит сохраняются.
- При явной смене аккаунта в соседней вкладке прежняя показывает вход; обновление/прямая ссылка не принимают нового пользователя без ввода учётных данных. Другой сеанс не завершается. Вкладки одного аккаунта разрешены. Подробности несекретной привязки UserId, сигнала BroadcastChannel и серверного X-Dean-Account — в [архитектуре](../ARCHITECTURE.md).

Первоначально добавленный пункт смены аккаунта в меню удалён по последующему уточнению пользователя; обычный выход сохранён.
