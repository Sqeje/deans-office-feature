# Срез 9 — интерфейс уведомлений

Цель: студент видит ленту, непрочитанные сообщения, счётчик, пустое состояние и примеры об оценках, расписании, заявках.

Границы: frontend-демонстрация; без API, миграций, новых прав, публикации сотрудником и событий соседних модулей (срез 10). Расписание пока заглушка; успеваемость и заявки серверные, вымышленные сообщения с ними не интегрируются.

Решение: Notifications владеет типизированными фикстурами и React-состоянием. Общий источник для ленты, последних трёх сообщений главной и счётчиков двух оболочек. Прочтение одного/всех — в памяти до перезагрузки, сброс при смене пользователя/выходе. Состояния: наполнено, пусто, загрузка, ошибка с повтором; явный переключатель восстанавливает фикстуры. Связанный объект — подпись с объяснением отсутствия перехода. Даты ISO 8601, ru-RU, Europe/Moscow. Доступ через существующий кабинет.

Общие изменения: Cabinet — подключение провайдера и счётчика; PerformanceShell — счётчик; главная — модульная сводка вместо независимой фикстуры. Сеанс, Kernel, реестр маршрутов, OpenAPI без изменений. Стиль по DESIGN.md, изображения не открывались.

Последовательность: модель/фикстуры/состояние → лента и состояния → подключение главной/навигации → тесты и визуальная проверка → саморевью и текст PR.

Проверки: Playwright — сортировка и категории, прочтение/все/нулевой счётчик, синхронизация оболочек и главной, перезагрузка/смена аккаунта, пусто/загрузка/ошибка/повтор, отсутствие сеанса. Визуально — desktop и 360 px, длинный текст, клавиатура, 200%; размеры 390–1440 без переполнения. dev.ps1 doctor/check (Docker); при отсутствии — документированный локальный путь с отдельной PostgreSQL. Фактические ограничения фиксировать ниже.

Статус: feature/notifications-ui; исходная frontend-сборка прошла; doctor прошёл с доступом к Docker вне песочницы. Реализация завершена и проверена в согласованных frontend-границах. 14.11.2026 пользователь явно разрешил commit, push, создание PR и merge.

Визуальная проверка: просмотрены снимки 360/1440/200%; найдено избыточное увеличение высоты нижней навигации из-за бейджа в потоке. Бейдж размещён возле иконки на мобильной навигации; тексты ленты получили относительную высоту строки для увеличения 200%.

## Приёмка и демонстрация

1. Войти студентом, открыть `/student/notifications`: три категории, две непрочитанные записи, даты по Москве, счётчик 2.
2. Прочитать одну запись, затем все: счётчики уменьшаются, при нуле общий action отключён и бейдж меню исчезает. Перейти на главную и в успеваемость — состояние совпадает.
3. Перезагрузить: исходные две непрочитанные записи возвращаются. Выход и новый вход также сбрасывают демонстрацию.
4. Выбрать пустую ленту, загрузку, ошибку. «Повторить» возвращает наполненную ленту. Проверить предупреждение о вымышленных связанных записях.

Саморевью: проверены область провайдера, сброс по userId/выходу, общий источник, сортировка без мутации фикстур, отсутствие API/хранилища и новых прав, локальность CSS. Дополнительно 14.11.2026 отдельный агент выполнил независимое ревью, существенных дефектов не обнаружено.
