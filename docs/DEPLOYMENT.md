# Linux

1. Подготовьте Linux VPS с Docker Engine и Compose plugin. Выберите хостинг с доступом из России. Создайте DNS A-запись домена на IP сервера; AAAA добавляйте только при рабочем IPv6.
2. Разрешите входящие TCP 80/443 и SSH; PostgreSQL и API наружу не открывайте.
3. Скопируйте репозиторий. `cp .env.example .env`; `chmod 600 .env`. Заполните уникальные пароли и `SITE_ADDRESS=dean.example.org`. Используйте URL-безопасные случайные пароли БД без `;`, чтобы не ломать connection string. Для демо нужны Demo__Password1, Demo__Password2 и Demo__StaffPassword длиной от 12, с верхним/нижним регистром, цифрами и символом.
4. `docker compose up -d --build`. Initialize применяет миграции и seed, затем запускается API. `docker compose logs initialize api web`; `docker compose ps -a`.
5. Откройте https://dean.example.org. Caddy получает публичный TLS-сертификат. Проверьте /health, студенческие аккаунты и сотрудника и выход. Проверьте ссылку отдельно с телефона в российской сети без VPN.
6. Для обновления: резервная копия БД, получение проверенной версии, `docker compose up -d --build`. При ошибке initialize не запускайте новую API вручную, изучите журнал.

Резервная копия (Linux): `docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql`. Храните копии вне сервера с ограниченным доступом; регулярно проверяйте восстановление на отдельной БД. Сохраняйте также том keys: потеря ключей завершит существующие сеансы. Не используйте `docker compose down -v`: это удаляет данные.

После создания демо-аккаунтов можно поставить Demo__Enabled=false. Повторный seed не меняет пароли; для их смены используйте отдельную контролируемую административную процедуру Identity. Не публикуйте .env, дампы и логи с секретами. Внешние шрифты/CDN в приложении не используются.
