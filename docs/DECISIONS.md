# Решения

- Docker-сборки используют SDK 10.0.402-noble: образ 10.0.403-noble на проверенной Docker Desktop 4.99.0 воспроизводимо выдаёт mmap error 22 и содержит пустые файлы SDK даже после повторной загрузки. 10.0.402 проверен отдельно через dotnet --info. Пакеты приложения и runtime остаются 10.0.14; контейнер проверок также получает shared runtime 10.0.14. Повышать SDK следует после проверки запуска нового образа.

- .NET/EF/Npgsql 10 совместимы; React/Vite и Tailwind 4 не требуют отдельного сервера в production. Node 24 используется только для сборки. Версии npm зафиксированы lock-файлом.
- Identity с серверными cookies уменьшает объём собственной безопасности. Не используем публичную регистрацию: тестовые пользователи создаются отдельной командой.
- Same-origin через Caddy устраняет потребность в CORS. Локально Compose тоже использует HTTPS; отдельный dev-режим допускает HTTP только на машине разработчика.
- Общий DbContext выбран ради простых транзакций и миграций V1. Логические границы модулей сохраняются папками, контрактами и правилами ревью.
- Миграции/seed — отдельный одноразовый процесс перед API; несколько реплик не должны параллельно изменять схему.
- Демо-пароли поступают только из окружения; повторный seed не сбрасывает существующие пароли. Identity хранит только хеши.
- Публичный хостинг не создан: нужен сервер, домен и разрешение владельца. Доступность из России проверяется на выбранном хостинге из российской сети; конфигурация сама по себе этого не гарантирует.

- Kernel 2: ApplicationUser отделён от StudentProfile. Один университет на аккаунт, серверный набор ролей без самоназначения. Права сотрудника назначаются отдельно на каждую операцию и группу; публичная область абитуриента не требует аккаунта.
- Регистрация модулей явная, модели конфигурируются внутри модулей. Межмодульные интерфейсы принадлежат поставщику возможности.
- Интеграции имеют типизированные этапы получения, интерпретации и применения. Источник владеет импортированными полями. Нет удаления по отсутствию и автоматического угадывания связей. Объём пакета и тайм-аут задаёт потребитель. Атомарность и idempotent upsert обеспечивает applier модуля; транспорт и планировщик не входят в Kernel.
- Ошибки — Problem Details с code/traceId; аудит сотрудника сохраняется в транзакции предметного изменения. Downgrade после отделения аккаунтов запрещён, поскольку сотрудники не имеют старой обязательной группы; восстановление — из резервной копии.
