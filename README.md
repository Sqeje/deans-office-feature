# Цифровой деканат будущего

Кабинеты студента и преподавателя для AI Challenge MGIMO. Работают вход, выход, общий сеанс, профиль, серверное личное расписание студента и преподавателя, ближайшая пара студента на главной. Преподаватель с разрешением редактирует только свои локальные пары, не всё расписание группы. Каталог групп и чужие расписания преподавателей используют отдельное frontend-демо; успеваемость, обращения и уведомления остаются заглушками. Все демонстрационные данные вымышлены.

Стек: React/TypeScript/Vite, Tailwind 4 и компоненты shadcn/ui; ASP.NET Core Identity / EF Core / Npgsql 10; PostgreSQL 17; Caddy и Docker Compose. Архитектура — модульный монолит.

## Устройство проекта

**Проект** — это папка с исходным кодом интерфейса (frontend), сервера (backend) и настройками запуска. Браузер не может запустить всю эту папку напрямую: приложение сначала нужно собрать, затем запустить.

Когда вы выполняете `dev.ps1 up`, скрипт обращается к **Docker Compose**. Compose читает `compose.yaml` — инструкцию, какие части приложения нужны и как их соединить. Docker по файлам `Dockerfile` собирает **образы**: подготовленные версии приложения с необходимыми зависимостями. Затем создаёт и запускает из них **контейнеры**. Для PostgreSQL используется готовый образ.

```text
Исходники в папке проекта
        ↓ dev.ps1 up: сборка по Dockerfile
Образы — подготовленные версии приложения
        ↓ Docker Compose создаёт и запускает контейнеры
Работающий сайт, API и база данных
        ↓
Браузер открывает https://localhost
```

У проекта четыре контейнера:

| Контейнер | Что делает простыми словами |
|---|---|
| `web` — интерфейс и Caddy | Даёт браузеру доступ к сайту. Отдаёт собранные страницы React, CSS и JavaScript, а запросы к `/api` передаёт backend. Принимает HTTPS на порту 443. |
| `api` — backend | Выполняет серверную логику: проверяет логин и пароль, создаёт сеанс, выдаёт профиль и проверяет права доступа. Читает и сохраняет данные в PostgreSQL. |
| `db` — PostgreSQL | Хранит аккаунты, хеши паролей, профили и остальные данные. Браузер напрямую к ней не обращается. |
| `initialize` — подготовка | Перед запуском API обновляет структуру БД миграциями и, если включён демо-режим, создаёт недостающие тестовые аккаунты. После успешной подготовки завершается: `Exited (0)` — нормально. |

Во время работы запросы проходят так:

```text
Браузер → web (Caddy) → api → db
             ↓
       файлы интерфейса
```

**Откуда берутся логины и пароли?** Демо-логины заданы в коде подготовки, а случайные пароли скрипт первого запуска записывает в локальный файл `.env`. Контейнер `initialize` получает эти настройки и создаёт аккаунты в БД; `api` затем проверяет вход. Отдельного контейнера, который показывает или выдаёт пароли пользователю, нет. Таблица логинов и названий полей `.env` приведена ниже.

**Где живут данные?** PostgreSQL хранит их в отдельном **томе Docker** — постоянном хранилище вне контейнера. Поэтому контейнеры можно заменить новой сборкой, сохранив БД. Файл `.env` находится в папке проекта и тоже должен сохраняться. Изменение пароля в `.env` не меняет пароль уже созданного аккаунта.

**Почему правки кода не появляются после Start/Stop?** Образ содержит код на момент сборки, а контейнер запускает конкретный образ. Кнопки Start/Stop/Restart в Docker Desktop управляют существующим контейнером и не собирают исходники. После правок выполняйте `dev.ps1 up`: он пересоберёт нужные части и обновит контейнеры. Docker Desktop показывает и управляет ими; держать терминал с командой запуска открытым после её завершения не требуется.

## Локальный быстрый старт

### Локальная установка — один раз

1. Установите [Git](https://git-scm.com/downloads) и [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/). В Windows используйте Linux containers с WSL 2; выполните подсказки установщика и перезагрузите компьютер, если потребуется. На Linux нужны Docker Engine, Compose plugin и PowerShell 7 (`pwsh`).
2. Запустите Docker Desktop и дождитесь готовности Engine. Убедитесь, что на диске хранения Docker достаточно места: папка проекта на D: сама по себе не переносит хранилище Docker с C:.
3. Получите у команды URL репозитория. Откройте PowerShell и выполните, подставив URL:

   ```powershell
   git clone <URL-репозитория> deans-office
   cd deans-office
   .\dev.ps1 doctor
   ```

   Если проект уже скачан, откройте его папку в Проводнике и выберите «Открыть в терминале». В этой папке должны находиться `dev.ps1` и `compose.yaml`. У автора проекта текущий путь: `D:\_Production\Projects\Software\deans-office-feature`; у остальных он будет своим.

Для контейнерного запуска устанавливать .NET, Node.js/npm и PostgreSQL на компьютер не требуется. Если PowerShell блокирует скрипт политикой выполнения, сообщите агенту точный текст ошибки; не отключайте системную политику вслепую.

### Локальный запуск — каждый день

1. Запустите Docker Desktop.
2. Откройте PowerShell в корне проекта и выполните:

   ```powershell
   .\dev.ps1 up
   .\dev.ps1 status
   ```

3. Дождитесь успешного завершения команды. Первый запуск скачивает образы и зависимости. Ожидаемое состояние: `db` работает и healthy, `api` и `web` работают, `initialize` завершился с кодом **0**.
4. Откройте **https://localhost**. Для локального сертификата Caddy браузер может запросить доверие; это отдельная настройка локального HTTPS. Проверка API: [health](https://localhost/health) должна показать `Healthy`.
5. Откройте файл `.env` в корне проекта редактором и возьмите учётные данные:

   | Логин | Поле с паролем в `.env` |
   |---|---|
   | `student1@demo.invalid` | `Demo__Password1` |
   | `student2@demo.invalid` | `Demo__Password2` |
   | `staff@demo.invalid` | `Demo__StaffPassword` |

   В серверном демо первый студент относится к ПИ-21, второй — к ПИ-22. `staff@demo.invalid` — тестовый преподаватель Иван Викторович Лебедев: его пары привязаны к аккаунту в обеих группах. В расписании доступны «Моё расписание», «Все расписания», «Редактировать расписание». Править можно только собственные локальные пары; другие пары той же группы запрещены сервером. Импортированные записи доступны для просмотра. Повторный запуск сохраняет пароли и ручные правки. XLSX выгружается из открытого режима; серверные демоданные и отдельный демонстрационный каталог подписаны раздельно.

   Проверьте вход, профиль, обновление страницы и выход. Для двух независимых аккаунтов используйте обычное и приватное окно. `.env` не публикуйте и не отправляйте в чат.

   Вкладки одного браузерного профиля разделяют cookie. Для входа в другой аккаунт сначала выйдите через меню профиля. Отдельной функции переключения аккаунтов нет. При выходе или замене аккаунта старые вкладки показывают экран входа, не завершая новый сеанс. Обновление старой вкладки не переключает её на новый аккаунт автоматически. Одновременные вкладки одного аккаунта разрешены.

### Команды на каждый день

Все команды выполняются в корне проекта. На Linux: `pwsh -File ./dev.ps1 up` и аналогично для остальных действий.

| Задача | Команда |
|---|---|
| Проверить доступность Docker и Compose | `.\dev.ps1 doctor` |
| Собрать текущий код и запустить/обновить сайт | `.\dev.ps1 up` |
| Посмотреть состояние контейнеров | `.\dev.ps1 status` |
| Посмотреть последние журналы | `.\dev.ps1 logs` |
| Остановить и удалить контейнеры, сохранив тома с данными | `.\dev.ps1 down` |
| Проверить код в отдельном тестовом окружении | `.\dev.ps1 check` |

После изменения кода или получения обновлений из Git выполняйте **`up`**. Для полного перезапуска: `down`, затем `up`. `check` не обновляет работающий сайт: он собирает и тестирует отдельную копию. Подробности и отчёты: [AUTOMATION.md](docs/AUTOMATION.md).

### Образ, контейнер и данные — три разные вещи

- **Исходники** — файлы проекта, которые вы и Codex редактируете.
- **Образ (image)** — результат сборки: код и зависимости, подготовленные для запуска. Может существовать несколько версий образа. Образ с привычным именем не обязательно содержит последние изменения исходников — сначала нужна сборка.
- **Контейнер (container)** — экземпляр конкретного образа с настройками запуска. Уже созданный контейнер продолжает использовать свою версию образа, даже если рядом собран новый.
- **Том (volume)** — отдельное постоянное хранилище, например для PostgreSQL. Данные переживают замену контейнера.

```text
Изменение файлов → dev.ps1 up → сборка образа → обновление контейнера → новый сайт
```

В Docker Desktop группа `dean-dev-…` объединяет контейнеры проекта. **Stop/Start и Restart запускают существующую версию и не собирают изменённый код.** Для обновления используйте `dev.ps1 up`: он собирает нужные образы и пересоздаёт изменившиеся контейнеры. Этот режим не имеет автоматического обновления при сохранении файла.

### Что происходит при инициализации

`up` создаёт `.env`, если его нет, генерирует случайные пароли для незаполненных/CHANGE_ME значений и сохраняет уже заполненные настройки. Затем запускается цепочка:

```text
PostgreSQL готов → initialize: миграции → демо-данные → API → Caddy и интерфейс
```

Миграции обновляют структуру БД. При `Demo__Enabled=true` создаются недостающие вымышленные университет, группа и аккаунты. Пароли хранятся в БД в виде хешей Identity. Повторная инициализация не меняет пароль существующего пользователя: правка `.env` не является сбросом его пароля. Не удаляйте `.env` при сохранённой БД; пароль PostgreSQL тоже не меняется простой правкой этого файла.

## FAQ

**Почему сайт работает, хотя npm не находится в терминале?** Docker использует Node/npm внутри сборочного контейнера. После сборки Caddy отдаёт готовые HTML/CSS/JS; локальный npm для этого не нужен.

**Почему `localhost` без порта?** `https://localhost` означает порт 443 — стандартный для HTTPS. Caddy принимает его и направляет `/api` в backend на внутренний порт 8080. PostgreSQL на 5432 доступен только внутри Docker. При разработке без контейнеров Vite обычно использует 5173 — это другой режим.

**Почему после Start/Restart виден старый интерфейс?** Контейнер запущен из прежнего образа. Выполните `dev.ps1 up`, затем обновите страницу. Не запускайте параллельно старый Vite и не путайте его URL с HTTPS-сайтом.

**Почему initialize остановлен?** `Exited (0)` означает успешное завершение одноразовой подготовки. Другой код — ошибка; смотрите `dev.ps1 logs`.

**Что делать при «Не удалось связаться с сервером»?** Сохраните точный URL, время и шаг ошибки. Выполните `status`, `logs`, проверьте `/health`. Работающий контейнер и успешный health ещё не доказывают рабочий вход. Передайте агенту эти сведения без паролей и cookies; попросите проверить конкретный запрос, CSRF и вход. Не удаляйте БД для исправления входа.

**Почему неправильный пароль после изменения .env?** Seed не сбрасывает существующие пароли. Нужна отдельная процедура смены через Identity. Не пересоздавайте БД ради этого без согласования.

**Сохранится ли БД после остановки/пересборки?** Да, при обычном `down` и `up`. Удаление тома или `down -v` уничтожит данные. Не используйте глобальные Docker prune для обычной диагностики.

**Что означает суффикс dean-dev-…?** Он вычисляется из пути к папке проекта. Другой clone/worktree получает другое имя и отдельные тома. Не смешивайте `dev.ps1` с ручным `docker compose up`: ручной запуск может создать другую копию проекта и другую БД. Двум копиям также нельзя занимать одни порты 80/443.

**Как работать без Docker с быстрым обновлением интерфейса?** Это дополнительный режим: [LOCAL_ENVIRONMENT.md](docs/LOCAL_ENVIRONMENT.md). Там нужны отдельные .NET, Node/npm и PostgreSQL. Сначала освойте основной контейнерный путь.

## Продолжение фундамента: Kernel

Три области: `/student`, `/staff`, `/applicants`. Старые `/app/*` перенаправляются в кабинет студента. Учётная запись отделена от студенческого профиля. Разрешения сотрудника выдаются по операциям и группам, общевузовские — отдельно. Реализованы чтение личного расписания, редактирование локального занятия уполномоченным сотрудником и технический демонстрационный импорт. Реальные университетские источники и остальные рабочие операции — последующие срезы.

[Как подключить модуль и источник](docs/EXTENDING.md), [следующие срезы](docs/SLICES.md). Миграция KernelIdentity переносит прежние аккаунты/группы без смены паролей. Перед обновлением сохраните резервную копию: автоматический downgrade к схеме без сотрудников запрещён, восстановление выполняется из копии. Демо-seed требует три разных пароля аккаунтов и не сбрасывает уже существующие.
